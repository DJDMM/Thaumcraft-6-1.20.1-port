# Brain in a Jar — проверка BETA26 и перенос 0.24

Авторитет: `work/Thaumcraft-1.12.2-6.1.BETA26.jar`, SHA-256
`9425f8643581b27ff8845b087c8bc6fc10425a32942f1a3f0e265ce6b38f7b5f`.
Проверены `javap -c -p` для `TileJarBrain`, `BlockJarBrainItem`,
`BlockJar` и общего `TileJarRenderer`. Исходный снимок используется для
читаемых названий, а не для исправления подтверждённых особенностей JAR.
Это устройство TC6, не стол/головоломка TC4.

## Исходный контракт

- Вместимость `xpMax = 2000`. Ближайшая сфера XP выбирается по квадрату
  расстояния до центра из **AABB блока, расширенного на 8 по трём осям**.
  Это не сфера радиуса восемь; угловые объекты тоже подходят. Стены не
  проверяются и не блокируют притяжение.
- Один ближайший объект получает ускорение. Для `d=(центр−позиция)/25`
  и `r=|d|` множитель `(1−r)^2`; прибавка к скорости по X/Z равна
  `d/r * множитель * .3`, по Y — `d/r * множитель * .5`.
- При `eatDelay == 0` и запасе ниже 2000 съедаются **все** сферы,
  пересекающие AABB `(x−.1,y−.1,z−.1)` — `(x+1.1,y+1.1,z+1.1)`.
  Их значения суммируются, объекты удаляются, звучит vanilla eat `.1`.
  Проверка вместимости находится перед циклом, не внутри него:
  `1999 + 7 + 3 = 2009`, затем **в начале следующего тика** запас
  обрезается до 2000. Исходная потеря переполнения сохранена.
- Правый клик, в том числе с предметом и при приседании, ставит
  `eatDelay = 40` независимо от результата. На сервере выбирается
  `nextInt(min(xp+1,64))`: допустим нулевой результат и максимум 63 XP.
  Запас сразу уменьшается на выпущенное количество; создаются настоящие
  `ExperienceOrb` по исходной последовательности vanilla XP split.
  Здесь нет уровней игрока, прямого начисления XP или требования владельца.
  После 40 полностью пропущенных callbacks захват возобновляется на 41-м.
- Сохранение и синхронизация BE содержат верхний `XP`; переносимый предмет
  использует нижний `xp` и показывает зелёную строку `N xp`. Задержка,
  вращение и вместимость не сохраняются. Разрушение возвращает одну банку
  с запасом в NBT, не отдельные сферы и не эссенцию. Пустая банка не имеет
  тега `xp`. Повторная установка восстанавливает настоящий запас.
- Comparator: `floor(xp/2000 *14) + (xp>0 ? 1 : 0)`.
  Enchanting power — пять для реального `TileJarBrain`, даже пустого.
  `BlockJar` задаёт hardness `.3`; унаследованная BETA26 resistance20
  даёт эффективную resistance12. Нет обязательного правильного инструмента.
  Bounding/collision box: `(3,0,3)` — `(13,12,13)` пикселей.
  Исследовательский помощник остаётся идентичностью физического `jar_brain`;
  его наличие не зависит от количества XP.

## Визуал и звук

Существующие оригинальные cuboids `LegacyBrainBlockModel`/`LegacyJarBlockModel`
и текстуры `brain2.png`/`jarbrine.png` повторно используются. Root-transform
`(.5,.01,.5)`, X180; мозг переносится `(0,−.8+bob,0)`, Y-interpolated-yaw,
Y−90, scale `.4`. `bob = sin(player.tickCount/14)*.03 + .03`.
Мозг плавно поворачивается к ближайшей сфере, иначе к игроку в шести блоках;
без цели target-yaw растёт на `.01`, текущий yaw приближается на `.04`.
Интерполяция проходит кратчайшую дугу через ±π. Оригинальные неиспользуемые
случайные поля `field_40061_d/field_40059_f` не влияют на этот рендер.

Клиентский вздох использует оригинальный `brain`, volume `.15`, pitch `.8..1.2`:
первый разрешён через 1500 миллисекунд, следующий через 5000..29999.
Клик использует `jar`, volume `.2`, pitch1. Все пять физических звуков
SoundType используют `jar`, volume `.5`, pitch1. Отложенное разрешение
sound registry необходимо: блоки регистрируются раньше звуков.

## Явные адаптации 1.20.1

- Авторитет XP находится на сервере; клиент не съедает и не удаляет объекты
  второй раз. Современная merged orb хранит `Count` отдельных старых сфер:
  кредит равен `getValue() * Count`. `Count` читается через публичную
  сериализацию самой `ExperienceOrb`, без отражения/доступа к private-полю.
- Ускорение при точном совпадении с центром не делит на ноль; отрицательный
  NBT XP отбрасывается. Сумма ограничена положительным int до следующего
  штатного clamp2000. Comparator ограничен легальным современным 0..15.
  Изменение из-за next-tick clamp теперь тоже сохраняется и синхронизируется.
- Захваченные объекты удаляются до отправки уведомлений/звука, чтобы модовый
  callback не мог повторно оплатить те же сферы. Граница переполнения сохранена.
- Brine использует современный translucent pass. Полная банка показывает
  нативную зелёную `ENTITY_EFFECT` частицу вместо оригинального FXDispatcher
  spark. Это визуальная адаптация, не утверждение совпадения всей FX-геометрии.
- Старые storage-free `catalog_visual` якоря загруженных чанков заменяются
  в общей bounded/fair END migration queue. Настоящие BE с XP не заменяются;
  принудительно чанки не загружаются. Chunk refresh заменяет класс BE клиента.

## Подключение и проверки

Новый пакет `thaumcraft.golemancy.jar` содержит `BrainJarModule`,
`BrainJarBlock`, `BrainJarBlockEntity`, `BrainJarBlockItem`,
`LegacyBrainJarMigration`, renderer и item extension.
Общий проект должен подключить `BrainJarModule.register(modBus)`,
route `CatalogBlocks.create` через `handlesBlock/createBlock`, а BlockItem
`jar_brain` через `new BrainJarBlockItem(block.get())`.
Клиентская регистрация: `BrainJarModule.BRAIN_JAR` -> `BrainJarRenderer::new`.
Существующий generic стеклянный asset/ID не изменяется.

API для реальных UI/QA: `xp()`, `eatDelay()`, `releaseXp()`;
настоящая установка использует нижний `ItemStack` тег `xp` и `setPlacedBy`.
Только явно отмеченные fixtures могут загружать `XP` через `load(CompoundTag)`.
`asItemStack()` возвращает переносимый предмет с нижним `xp`.
Регистрация исследовательского пути JARBRAIN и оригинальный infusion recipe
находятся в общем проекте; пакет не добавляет альтернативных рецептов/gates.

`BrainJarGameTests` определяет 11 содержательных сценариев: физический блок,
сила/выбор/AABB притяжения, contact overflow, merged Count, точный случайный
debit/split/zero-клик, 40-callback pause, сохранение/установка, реальное
разрушение, настоящий зарегистрированный ticker и theory aid, malformed-NBT,
bounded worker-safe migration. Здесь описаны определения тестов, **не их
успешный запуск**. Финальные серверные/client/build результаты записывает
общий `VALIDATION.md` только после настоящего прогона.

Original BlockJar returns UNDEFINED face shape on every side. The modern brain jar supplies an empty support shape, including CENTER support, so it does not become a hanging-lantern attachment; the server suite checks all six faces.
