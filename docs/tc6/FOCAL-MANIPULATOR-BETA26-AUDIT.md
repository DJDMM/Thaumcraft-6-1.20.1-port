# Конструктор фокусов — аудит Thaumcraft 6.1.BETA26

Эталон — закреплённый официальный JAR `Thaumcraft-1.12.2-6.1.BETA26.jar`, SHA-256
`9425f8643581b27ff8845b087c8bc6fc10425a32942f1a3f0e265ce6b38f7b5f`.
Удобный исходник `954022bb777b7546281fb36df8522f0ba6b43f81` проверен через
`javap -c -p` для `TileFocalManipulator`, `ContainerFocalManipulator` и пакетов редактирования.
Это конструктор TC6, не исследовательская шестиугольная головоломка старых версий.

## Подтверждённое поведение оригинала

- Блок `wand_workbench`, каменные звук/материал, без направленного состояния;
  непрозрачность и полнота рендера выключены, наследуемый collision box полный.
  GUI открывается обычным взаимодействием без дополнительной проверки исследования.
- Единственный слот принимает любой `ItemFocus`. Координаты слота `(31,191)`;
  главный инвентарь расположен слева в трёх колонках, hotbar сеткой 3×3.
- Дерево начинается `ROOT`. Пустой дочерний сокет заполняется выбранным
  доступным medium/effect. Замена узла отсекает его потомков; настройки узла меняют
  сложность. Medium и effect имеют собственные кольца и исходные иконки.
- Каждый конкретный тип узла получает множитель сложности `0.5*(k+1)` для своего
  k-го появления. Преобразование в целое происходит после добавления каждого узла.
  Кристаллы — один предмет каждого аспекта на каждый имеющий аспект узел;
  это не число единиц vis и не сложность.
- Все исследования узлов проверяются `knowsResearchStrict`; факт начала bare entry
  и старые PORT-алиасы недостаточны. ROOT тоже содержит metadata BASEAUROMANCY;
  порт опускает его избыточную проверку, поскольку TOUCH/FIRE требуют ту же запись.
- Создание требует `complexity*10 + maxComplexity/5` vis (целочисленное деление
  второго слагаемого), `max(1,round(sqrt(complexity)))` уровней XP и соответствующие
  кристаллы в **main inventory**, включая hotbar, без armor/offhand/Baubles.
- Creative обходится без XP, но оригинал всё равно проверяет и расходует кристаллы.
- Каждые 20 тиков table просит `min(20,remainingVis)` местной ауры. Нулевая аура
  приостанавливает процесс. С зарядником сверху обходятся позиции chunk offsets
  x=-1..1, z=-1..1 с фиксированной долей `requested/9`; остаток не перераспределяется
  по более богатым чанкам. При чтении ауры не должно загружаться новых чанков.
- При завершении изменяется текущий focus, удаляется кэш `color`, назначаются имя
  и пакет. Пустое/заменённое содержимое прекращает работу; потраченные XP,
  кристаллы и vis не возвращаются. Уже записанный старый пакет остаётся до успеха.
- Исходный рендер: focus вращается над `(0.5,0.8,0.5)`, кристаллы расходованных
  аспектов обращаются радиусом0.4 на высоте1.05; каждый аспект имеет два луча
  с deterministic seed `187+num²` и дополнительный светящийся спрайт.

## Подтверждённые ошибки оригинала и явные изменения порта

1. Сервер вычитает XP **до** проверки кристаллов. Отказ из-за нехватки кристаллов
   может уничтожить уровни XP. В порте сначала проверяются весь граф, исследования,
   focus, XP и все кристаллы, затем один серверный callback атомарно списывает оплату.
   Это согласованное исправление, а не утверждение о поведении BETA26.
2. GUI считает XP `min(1,round(sqrt(complexity)))`, сервер — `max(1,...)`.
   GUI порта показывает настоящий серверный расход.
3. Исходный packet позволяет подменить любое дерево по координатам без проверки
   открытого контейнера/расстояния/активного процесса. Порт проверяет live menu,
   container ID, block position, расстояние≤8 блоков, монотонную revision, bounded
   graph/NBT, допустимые settings и отсутствие активной оплаты. Изменение focus
   инвалидирует запоздавший пакет.
4. Ограничение сложности в исходнике проверяет GUI, а не `startCraft` сервера.
   В порте сервер тоже проверяет его. Циклы/недостижимые узлы/дубликаты/ложные parent
   и children отвергаются; массивы клиента не являются исполняемым серверным кодом.
5. Порт сохраняет отдельно оплаченные graph/input/remainingVis/tick phase; reload
   не списывает оплату повторно и не позволяет подменить план редактированием GUI.
   Отмена остаётся без возврата как в исходнике.
6. Кристаллы временных версий порта распознаются общей API совместимости; реальные
   crystal_essence проверяются по целому исходному top-level `Aspects` NBT. Лишние
   вложенные элементы не заменяют обязательный одиночный аспект с amount1.

## Реализуемая область0.16

Редактор и оплату проверяем для исполняемой цепочки ROOT → TOUCH → FIRE, с исходными
power/duration settings. Другие зарегистрированные части остаются явной справкой
со своими исходными исследованиями; недоделанная часть не создаёт рабочий focus.
Светящиеся лучи и предметы рендерятся современными API; исходные custom particle
billboard/sparkle адаптированы к штатным современным частицам. Ни один GUI preview
не создаёт предметов, не расходует aura и не выдаёт исследования.
